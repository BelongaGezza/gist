Flow reading view (virtualised, typography controls, TOC, in-document search) — **Q8 decided 2026-09-12: SwiftUI-native for v1.0.** Both `Text`-per-block-in-a-`LazyVStack` and a TextKit 2 `NSViewRepresentable` were prototyped first. Findings: TextKit 2 needed noticeably less code for equivalent functionality — real text selection, copy, and `showFindIndicator`-based find-highlighting came essentially free from `NSTextView`, whereas the SwiftUI version required hand-rolling match-range bookkeeping across `AttributedString` runs, and its find/scroll-to-match was measurably less robust on long documents (`ScrollViewReader.scrollTo` inside a `LazyVStack` can only reliably reach ids already laid out nearby, unlike `NSTextView.scrollRangeToVisible`). Selection/highlighting did prove structurally weaker in SwiftUI, not just theoretically riskier — but the decision went to SwiftUI-native anyway: cross-platform reuse (TextKit 2/`NSTextView` is AppKit-only; GIST also targets iOS, which would need a second, parallel `UITextView`-based implementation) and automatic `ThemeManager`/environment integration (no manual `NSColor`/`NSFont` syncing in `updateNSView`) outweighed the selection/find gap for v1.0. Revisit only if a later requirement (copy-to-clipboard, share-sheet quoting) makes real text selection non-negotiable. **Update 2026-09-12 (later still): built out past prototype quality**, closing most of §3.5's remaining checklist (virtualised rendering, full typography controls, TOC, in-document search, progress bar, scroll-position persistence, keyboard/trackpad navigation). Virtualised rendering was effectively already satisfied by the `LazyVStack`/`ScrollView` structure the Q8 prototype used (that's the whole point of `LazyVStack` — only on/near-screen rows are materialized), so no extra work was needed there; everything else is new: **Typography** — `TypographySettings` gained `fontDesign` (`ReadingFontDesign`: system/serif/rounded, wrapping `Font.Design` since that type isn't `CaseIterable`) and `lineSpacing` (`LineSpacingOption`: compact/regular/relaxed, added points not a multiplier). Revisiting this as a real synced backend field is a schema question (Q10), not something to force through today.
